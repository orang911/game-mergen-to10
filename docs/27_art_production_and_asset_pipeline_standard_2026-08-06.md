## 1. 项目视觉身份

### 1.1 核心题材

世界观由以下三部分混合组成：

- 奇幻魔法世界：发光水晶、元素能量、符文、传送门、魔法轨迹。
- 中世纪城堡：城墙、塔楼、城垛、石质道路、旗帜、守护据点。
- 轻蒸汽朋克：少量黄铜环、旧铜支架、圆润机械件、简化齿轮、阀门和能量装置。

“轻蒸汽朋克”是点缀，不是机械堆砌。一个物件通常只需要 1～2 个机械识别点，不允许塞满齿轮、活塞、管线和铆钉。

### 1.2 当前主风格

关键词：

> 明亮、轻度、圆润、Q版、清晰、休闲、色块化、低细节噪声、中高明度、适中饱和度、轻度手绘、柔和体积感。

当前战斗主画面优先采用：

- 明亮绿色草地；
- 米白或暖白的圆角石板路径；
- 蓝灰石质水晶基座；
- 高亮青蓝水晶；
- 青蓝 + 深海军蓝 HUD；
- 黄橙色主行动按钮；
- 颜色鲜明的圆角数字方块；
- 小体型、短手短脚、剪影明确的 Q 版怪物。

大厅、登录页、加载页、弹窗可以改变构图，但必须沿用同一套圆角、明度、材质与轮廓语言。

### 1.3 禁止方向

- 阴暗恐怖、末日、血腥、破损、脏污重度化。
- 黑紫色大面积压画面、过深海军蓝占据主体、强烈金属厚重感。
- 写实金属、真实照片、硬核机械、赛博朋克、现代枪械。
- 过强透视、夸张景深、复杂空间层次；战斗场景保持接近俯视的轻透视。
- 过量边框、外发光、阴影、粒子、齿轮、铆钉、小高光和纹理。
- 直接套用早期冰雪蓝白风格、旧吸血鬼幸存者式深色风格或与当前绿色草地版本不一致的旧 UI。

## 2. 信息层级与灰度控制

### 2.1 全局视觉优先级

战斗画面：

```text
水晶 / 当前关键反馈
→ 棋盘与可操作块
→ 主按钮或当前交互入口
→ 怪物与路径
→ HUD 数值
→ 环境装饰
```

大厅画面：

```text
中心水晶
→ 继续/开始挑战按钮
→ 元素能力与主要入口
→ 怪物
→ 城堡和环境
→ 次要货币与设置
```

结算画面：

```text
本局奖励
→ 最高合成数字、击杀怪物
→ 波次、分数、时间
→ 其他统计
→ 伤害构成与次级说明
```

弹窗画面：

```text
标题
→ 当前核心结果/选择
→ 主按钮
→ 说明文字
→ 次级装饰
```

### 2.2 灰度阶梯

- 背景：最轻、最低对比，保证场景存在但不抢操作。
- 路径和棋盘底：中低对比，形状清楚但不比方块亮。
- 棋盘方块、关键图标：中高对比。
- 水晶、主按钮、当前选中状态：最高局部亮度与最清晰边缘。
- 遮罩后的背景只做统一压暗，不使用重度高斯模糊。

禁止所有组件均为同等明度、同等描边、同等饱和度。画面“平铺”通常就是缺少上述层级。

### 2.3 色彩映射

固定元素色不可随意互换：

| 属性 | 主色 | 使用规则 |
|---|---|---|
| 毒 | 黄绿色 / 草绿色 | 液滴、问号涡旋、毒雾；绿色只表达毒或自然环境 |
| 冰冻 | 青蓝 / 浅蓝 | 冰晶、雪花、寒气 |
| 闪电 | 明黄色 / 金黄 | 闪电符号、电弧；不得画成绿色 |
| 暴击 | 紫色 / 紫晶 | 星形晶体、爆点 |
| 火焰 | 橙色 / 红橙 | 火苗、燃烧、溅射 |
| 核心水晶 | 青蓝 | 全局最稳定的品牌色，可带少量白色高光 |
| 主按钮 | 明亮蓝或黄橙 | 同一界面只保留一个最高层级主按钮 |

每个小图标或怪物控制在 3～5 个主要颜色，不统计黑色外轮廓和极少量高光。

## 3. 造型、轮廓与材质语言

### 3.1 轮廓

- 方圆结合，以圆角矩形、圆鼓轮廓、短粗结构为主。
- 主体剪影必须在 96×96 像素下仍能辨认。
- 一个图标只允许一个主轮廓和 1～2 个辅助识别结构。
- 避免过多转折、尖刺、凹口、小挂件和悬浮碎片。
- 对称物件尽量对称；武器和法杖必须共享同一透视轴，不得歪斜。
- 水晶不宜细长，应偏短、厚、稳，切面数量精简。

### 3.2 明暗

- 使用大块面明暗，不用碎片化小切面。
- 高光、中间色、暗部必须形成完整大区块。
- 渐变自然但边缘清楚，不能变成模糊塑料。
- 金属以蓝灰、暖灰、青铜、旧铜表达，避免冷硬写实金属。
- 黑色描边可用深海军蓝替代纯黑，保持统一粗细。

### 3.3 阴影与光效

- 效果图允许轻微接触阴影和体积光。
- 用户明确要求“素材无阴影”时，独立切图源不保留投影、外发光或地面反射。
- UI 按钮不使用大面积黑色投影；靠边框、内高光、色阶和按下位移表达状态。
- 特效只围绕主体，不得串到其他图标或越过安全区。

## 4. 布局不可变规则

### 4.1 参考角色必须先分类

每次生图前明确每张参考图的角色：

| 角色 | 权限 |
|---|---|
| `LAYOUT_REFERENCE` | 功能位置、尺寸比例、路径、棋盘、HUD、按钮和安全区的唯一结构依据 |
| `STYLE_REFERENCE` | 色彩、材质、圆润度、轮廓、光照与细节密度依据 |
| `CONTENT_REFERENCE` | 必须出现的水晶、怪物、图标、文案或具体对象依据 |
| `EDIT_TARGET` | 在原图上修改；未点名的部分必须保持不变 |

不得把风格参考误当成布局参考，也不得把布局参考中的旧美术照搬进新方案。

### 4.2 战斗核心布局锁定项

若用户未明确要求改布局，以下全部锁定：

- 竖屏比例与安全区；
- 顶部暂停、波次、时间、货币位置；
- 怪物路径的起点、终点、每一个转弯、方向和宽度；
- 路径是否闭环；原图不是闭环时禁止擅自闭环；
- 魔法门朝向，必须朝向路径，透视合理；
- 水晶塔位置、占地和相对棋盘关系；
- 5×5 棋盘位置、大小和格子数量；
- 底部技能能量区、即时道具区、按钮槽位；
- 怪物行进方向和出生/到达逻辑。

用户说“合成部分整体上移”时，只移动棋盘及与它绑定的组件，不应重构整屏。

### 4.3 “只做优化”的含义

允许修改：

- 清晰度、分辨率；
- 边缘抗锯齿；
- 色阶过渡；
- 材质可读性；
- 局部色彩统一；
- 不改变形状的透视校正；
- 小范围对齐、间距和边缘修复。

禁止修改：

- 主体轮廓；
- 元素数量；
- 颜色身份；
- 功能位置；
- 路径；
- 原设计的阶段差异；
- 用户未提出的装饰和功能。

## 5. 分类美术标准

### 5.1 数字棋盘

- 固定为 5×5。
- 方块圆角、厚实、色块明确，数字大且居中。
- 数字字体由程序绘制，正式块底不烘焙数字。
- 不要复杂纹理；依靠上下明暗、内高光和细描边增加体积。
- 棋盘边缘使用草边、石质或轻量框体，不使用过重机械外框。
- 棋盘是玩法主体，必须比路径背景更清晰，但不能压过水晶和当前交互反馈。

### 5.2 九级水晶塔

- 9 级必须保持原始元素、颜色、级别演化和基座设计。
- 若任务是“改变透视”，只能调整统一俯视角度、底座椭圆透视和投影方向。
- 若任务是“高清重置”，不能改变各级水晶颜色：1～3 蓝、4 青、5 紫、6 粉、7 红橙、8 金黄、9 彩虹。
- 三行三列展示时，各格中心、主体占比和底部基线统一。
- 单独切图时保留相同画布、锚点和基线，方便游戏中无跳动替换。
- 战斗内水晶通常使用轻俯视三分之四角；不能继续使用正面立绘透视。

### 5.3 怪物

首批阵容为“3 个种族 × 3 个装备阶段”：

1. 史莱姆：软糖史莱姆、蘑菇史莱姆、铁壳史莱姆。
2. 哥布林：小哥布林、锅盔哥布林、方盾哥布林。
3. 小僵尸：布衣小僵尸、桶盔小僵尸、铁甲小僵尸。

统一要求：

- 大脑袋、小身体、短手短脚；
- 圆角方形或圆鼓身体；
- 表情简单、轻松，不恐怖、不血腥；
- 装备阶段主要通过单一装备剪影区分；
- 普通怪相对尺寸 0.9～1.0；装备怪 1.0～1.1；重甲怪 1.1～1.2；
- 重甲怪最大不超过普通怪 1.2 倍；
- 场景中的怪物是次级信息，不应比水晶或棋盘更亮、更大。

### 5.4 图标

图标目标是“极度简化且可读”，不是小型插画。

- 先检查纯黑剪影，再添加颜色。
- 主轮廓占画布约 68%～78%，四周留足安全边距。
- 只保留能表达功能的最少对象。
- 少用箭头；若必须用，保持粗、短、单一方向。
- 不使用文字、数字、Logo、卡牌边框和复杂背景。
- 同批图标使用相同三分之四角、光源、描边和精细度。
- 512×512 或更大绘制，必须缩小至 96×96 验收。
- 绿色毒、黄色闪电、蓝色冰、紫色暴击、橙红火焰的色彩不能混淆。

功能图标示例：

- 星阶锻造锤：锤 + 单颗晶块 + 上升含义；不堆齿轮。
- 万象铸数盘：圆盘 + 中心晶块 + 单一循环箭头。
- 命运洗牌箱：箱体 + 3 颗色块 + 一个交换符号。
- 双生晶铸模：两个相同晶块 + 对称底座。
- 王城魔导炮：粗炮管 + 城垛圆座 + 蓝晶炮口。
- 火龙投石机：投石臂 + 火晶石；龙形只保留最简识别点。

### 5.5 卡牌

- 卡牌分金色、紫色两个等级，结构一致但边框、横幅和卡背纹章必须不同。
- 当前游戏是轻度风格，禁止厚重暗金、复杂雕花和强外发光。
- 卡牌正面、卡背、横幅、星星、等级角标、中心图标必须可独立拆分。
- 卡牌底板不烘焙名称、描述、星级数字。
- 星星要提供亮/暗两个状态；横幅需要支持九宫格或固定尺寸批量复用。
- 卡牌在游戏实际尺寸下首先读到中心图标，其次才是名称与星级。

### 5.6 顶部 HUD

- 暂停、波次、计时、货币使用同一圆角蓝色语言。
- 外框为清晰青蓝边，内底为深蓝，但整体不能过黑。
- 文字为程序字；正式底板不烘焙“第 8 波”“00:45”“1804”等数据。
- 声音按钮需提供开/关状态；暂停需提供默认/按下状态；可能变化的图标必须独立。
- 波次与计时分隔依靠独立容器、留白或小图标，不使用生硬竖线。

### 5.7 底部 HUD

- 左侧为技能能量面板，右侧为即时道具按钮槽。
- 面板与按钮统一蓝色、绿色、紫色、灰色分区。
- 能量槽、技能徽章、换位、法杖、锁具均需独立资源。
- 正式生产图不烘焙“技能未激活”“0/100”、角标数字和次数。
- 状态至少包括：默认、按下、禁用、锁定、选中、可操作。
- 用户要求无阴影时，按钮不得带投影；状态依靠色阶、亮度、描边和轻微缩放区分。

### 5.8 道具/印记选择弹窗

- 当前标题优先使用“道具选择”，除非功能文档明确仍叫“选择合成印记”。
- 三卡布局保持轻量：浅蓝卡身、蓝色标题区、圆润边角、图标占主视觉。
- 未解锁道具仍显示图标和名称，只做置灰、锁定和“看广告解锁”入口。
- 广告按钮必须有播放图标，且不能遮挡卡片内容。
- 新出现道具有独立“新”角标。
- 选中卡轻微放大，并提供清晰的选中边框或底光；不要同时堆叠三种选中效果。
- 描述区随当前点选道具变化。
- 正式资源中卡名、描述、广告文字、按钮文字均由程序绘制。

### 5.9 节点完成/关卡完成弹窗

- 保留实际内容，例如标题“1-1 完成”、说明“水晶、棋盘与能量状态将带入下一关。”和按钮“继续前进”。
- 标题可采用紧凑的蓝色装饰牌/软横幅，两侧仅保留简单菱形点缀。
- 主体为浅冰蓝或蓝紫色圆角信息板；禁止旧式纯深蓝大黑框。
- 主按钮使用明亮黄橙色，保持最高行动层级。
- 不新增奖励、星级、货币、关闭按钮或第二按钮，除非策划明确要求。

### 5.10 结算界面

- 胜利/失败共用结构，可有“本局战绩 / 本局卡组”双页签。
- 奖励必须是首要信息区，使用独立暖黄色奖励背板。
- 最高数字和击杀怪物为第二层级的大统计卡。
- 波次、时间、分数为第三层级横向摘要。
- 合成次数、最大单次合成、城堡耐久、漏怪等为小型分区框。
- 伤害构成为最低层级，使用三段简洁横条。
- 资源拆分必须包含：总面板、胜利/失败标题、页签默认/选中、奖励背板、大统计框、小统计框、伤害行、主/次按钮、图标。

### 5.11 大厅、登录与加载页

- 水晶为绝对中心；怪物次之；Logo 不应压过水晶和主按钮。
- 登录页可使用英文主 Logo `CRYSTAL GUARDIANS`，中文“晶核守卫”作为副标。
- 大厅可调整构图以增加张力，但按钮功能与安全区必须遵守实机布局。
- 加载页背景与 Loading 条分离；背景需提供去掉 Loading 条、百分比和提示文字的干净版本。
- Loading 条需拆分空槽、填充、装饰边框；百分比和“正在加载中”由程序绘制。

### 5.12 通用设置弹窗

- 使用正常主界面 + 半透明暗色遮罩。
- 面板为轻量蓝紫魔法机械风格，不占满全屏。
- 功能包含音乐、音效、帮助、隐私预留、关闭。
- 开关必须提供开/关两个清晰状态。
- 面板、标题、关闭按钮、开关底、开关滑块、功能图标需独立。

## 6. 特效、弹道、序列帧与视频

### 6.1 静态特效合集

- 当用户要求“全景合集”，必须按参考图完整网格输出，不得只生成一个效果。
- 每个格子效果独立，不共享尾迹、光晕或粒子。
- 主体方向、长度、发射端和命中端统一。
- 背景使用方便观察的深灰或纯色，但正式资源需透明。

### 6.2 循环特效

- 先确定主体固定锚点，所有帧主体外轮廓不得漂移。
- 只让内部旋涡、符文、粒子、亮度或环形光带运动。
- 8 帧适合简单呼吸/旋转；12 帧适合较顺滑旋转；16 帧适合复杂循环。
- 首帧和末帧运动趋势必须连续，不能复制同一帧硬接。
- 不改变主体尺寸、基线和中心。

### 6.3 序列帧表

- 512×512、4×4 时，每帧严格 128×128。
- 每个帧格主体中心完全一致，外轮廓不可抖动。
- 不画分隔线，不裁切，不跨格，不共享粒子。
- 输出顺序固定为从左到右、从上到下。
- 同时提供帧率建议和循环模式，例如 `12 fps, loop`。

### 6.4 视频

- 视频不是把静态图平移；必须有主体内部循环。
- 保持透明需求时优先输出透明序列帧；若目标平台视频不支持 Alpha，另提供绿幕/黑底预览。
- 用户要求“还原参考”时，运动阶段和节奏优先于新增风格化细节。

## 7. 从需求到效果图的工作流程

### 7.1 第一步：确认任务类型

必须先判断属于哪一种：

1. 新方案：允许改变构图，但内容和功能不变。
2. 风格迁移：布局完全锁定，只替换视觉语言。
3. 精确编辑：只改用户点名区域。
4. 高清重置：不改变设计，仅提高质量。
5. 独立素材生成：纯色背景或透明资源。
6. 切图：不再设计，只执行资源拆分。
7. 动效：保持主体和锚点，设计时间变化。

若用户说“继续”，应继续最近一个未完成且已确认的任务，不得退回更早方案或重新理解范围。

### 7.2 第二步：建立锁定清单

每次开始前在内部列出：

```text
不能变：布局、比例、路径、功能、文案、颜色身份、主体数量。
可以变：本轮用户明确指出的项目。
目标：要输出效果图、素材图、透明切图、视频还是项目替换。
```

只修改用户点名的变量。用户指出“画面太黑”时，不得顺带改布局；指出“按钮更亮”时，不得换场景。

### 7.3 第三步：效果图优先

- 未确认整体风格前，先输出完整效果图，不急于切资源。
- 第一轮重点确认构图、灰度、中心、按钮层级、路径可读性。
- 第二轮只处理用户指出的偏差。
- 文案错误不应通过整张重新生图反复消耗；正式文案最终由程序绘制。

### 7.4 第四步：视觉验收

至少检查：

- 是否保留功能布局；
- 路径起点、终点和方向是否正确；
- 水晶、棋盘、怪物是否在正确位置；
- 画面是否过黑、过重、过度空间化；
- 水晶与主按钮是否为视觉中心；
- 元素颜色映射是否正确；
- 图标和怪物是否匹配当前圆润风格；
- 文字是否准确或应改由程序绘制；
- 是否新增了未授权功能。

### 7.5 第五步：单变量迭代

一次修订只处理一个主要问题，例如：

- 只调亮整体灰度；
- 只减弱栏杆；
- 只调整魔法门朝向；
- 只上移棋盘；
- 只替换怪物风格；
- 只增加缺失的毒系元素。

不得在局部反馈后重新设计整张图。

## 8. AI 生图工作流程

### 8.1 工具选择

- 新效果图、插画、怪物、图标草案：可用内置 ImageGen。
- 用户明确要求 Flyne 或需要沿用 Flyne 工作流：使用 `flyne-game-art-production`。
- 裁切、重命名、抠图、排版和简单色彩调整：禁止浪费生图积分，应使用本地工具。
- 已有可编辑原生资源时，优先编辑原文件，不重新生成。

### 8.2 Flyne 默认规则

- 用户已授权正常生图积分扣除，不再逐次询问是否同意。
- 不得购买套餐、修改支付、账户或隐私设置。
- 默认模型：`Nano Banana Pro`；默认 2K、9:16，用户另有要求时按用户设置。
- 第一张图默认可视为风格参考，第二张图默认可视为布局参考，但必须结合用户说明确认。
- 上传控制不可用时，不要重复无效点击；直接用结构化提示词生成，并说明使用了提示词映射。
- 一次生成后先检查不可变项；仅当硬性布局错误时做一次针对性修正。

### 8.3 推荐提示词结构

```text
输出目标：要制作什么、比例与用途。
布局依据：哪张图是唯一结构依据，必须保持哪些位置、路径、尺寸和功能。
风格依据：哪张图只负责颜色、材质、圆润度、光照和细节密度。
内容依据：必须出现哪些水晶、怪物、图标和文案。
禁止项：不能新增什么、不能改变什么、不能采用哪些风格。
```

战斗画面必须明确锁定：

- 路径起点和终点；
- 每个主要转弯；
- 棋盘 5×5；
- 水晶位置；
- 顶部 HUD；
- 底部控制区。

### 8.4 高清重置提示词模板

```text
以输入图为唯一造型和内容依据。严格保持原轮廓、比例、颜色、元素数量、位置、功能和状态不变。
只做高清重绘：提高分辨率、抗锯齿、边缘清晰度、块面色彩、材质纹理和渐变过渡。
不得重设计、不得新增装饰、不得改变透视（除非本轮明确要求）、不得改变文案和图标状态。
```

### 8.5 独立素材提示词模板

```text
生成单个完整 UI/图标素材，主体居中，四周留安全边距。
不包含文字、数字、角标数值、投影、外发光、地面或其他 UI。
背景使用完全均匀的纯色抠图底，不含渐变、纹理、反射和光照变化。
保持与确认效果图一致的轮廓、颜色、材质和状态。
```

## 9. 效果图确认后的切图流程

### 9.1 原则

切图阶段不再进行美术重设计。切出的素材必须与确认效果图一致，不能“差不多”。

正式 UI 资源不得烘焙：

- 中文和英文文字；
- 数字、百分比、次数；
- 波次、计时和货币值；
- 红点数量；
- 动态星级；
- 动态描述；
- 可替换图标。

### 9.2 优先拆分清单

每个界面至少检查是否需要：

1. 背景无 UI 版本。
2. 前景环境装饰。
3. 遮罩。
4. 总面板/底板。
5. 标题底板。
6. 主按钮默认/按下/禁用/锁定。
7. 次级按钮默认/按下/禁用/锁定/选中。
8. 卡片或槽位默认/选中/锁定/广告可解锁。
9. 新角标、锁图标、播放图标、可升级角标。
10. 图标框、图标底、角标底。
11. 进度槽底、进度填充、分段刻度。
12. 页签默认/选中。
13. 独立装饰件。

### 9.3 素材来源优先级

1. 原始分层文件直接导出。
2. 从无字、纯色底的独立素材大图切出。
3. 使用确认图局部抠图。
4. 若抠图存在光污染、遮挡、缺角或分辨率不足，重新绘制独立素材。

不得把效果图中被文字覆盖、被图标遮挡或带复杂背景的区域硬裁成正式资源。

### 9.4 纯色底与抠图颜色

- 默认使用主体中不存在的纯色。
- 绿色素材不能使用绿幕；优先使用纯洋红 `#ff00ff`。
- 紫色素材不能使用洋红；可使用纯绿色 `#00ff00`。
- 蓝色高亮素材避免蓝幕。
- 纯色底必须完全均匀，无阴影、渐变、纹理、反射、地平面和光晕。

### 9.5 抠图工具

可调用：

```text
C:\Users\PC\Documents\koutu\release
```

使用要求：

- 先保留原始有底图，不覆盖。
- 输出 PNG RGBA。
- 避免去色损伤主体中的绿色、紫色和蓝色。
- 需要时使用边缘收缩 1px，而不是粗暴扩大透明阈值。
- 半透明发光不是正式 UI 底板必需内容；优先单独拆光效层。

### 9.6 边缘验收

透明素材必须分别放在以下背景检查：

- 纯白；
- 浅灰；
- 纯黑。

不允许出现：

- 绿色或紫色杂边；
- 白色毛边；
- 半透明缺口；
- 黑边断裂；
- 轮廓被削薄；
- 边缘锯齿；
- 残留文字和背景纹理。

### 9.7 裁切和锚点

- 透明画布保留 4～12px 安全边距，具体按素材尺寸确定。
- 同组状态必须相同画布尺寸、中心和基线。
- 按钮默认/按下/禁用不能因裁切不同产生跳动。
- 九级水晶、怪物动画、序列帧必须共享同一锚点。
- Godot 中常用中心锚点或底部中心锚点必须在资源说明中标记。

### 9.8 九宫格资源

面板和可伸缩按钮必须提供 NinePatch 安全区说明：

- 四角和装饰不可拉伸；
- 中央纯色区可拉伸；
- 边框中段只允许单方向拉伸；
- 文本安全区不能压到边框和角饰。

建议附带：

```text
patch_left / patch_top / patch_right / patch_bottom
content_margin_left / top / right / bottom
```

## 12. 入库与游戏替换流程

1. 备份当前资源或使用新版本文件名，禁止直接覆盖未知来源的用户文件。
2. 将透明 PNG 放入对应 `assets/runtime` 模块。

6. 设置 TextureRect 拉伸模式、NinePatch 边距、锚点和最小尺寸。
7. 检查默认、按下、禁用、锁定和选中状态。
8. 在实际竖屏分辨率运行截图。
9. 对比确认图，检查位置、比例、颜色、清晰度与交互区域。
10. 执行 Godot 解析、主场景 Headless 启动和 Web 冒烟，确保无关键错误。

仅当用户明确说“去游戏目录替换并实现”时，效果图任务才自动延伸到代码和资源替换。单纯“看效果”“出方案”“切图”不等于授权修改运行场景。

## 14. 常见错误与纠正方法

### 14.1 只换颜色，没有真正统一风格

错误：保留旧式厚重框体，仅把颜色改成蓝紫。  
纠正：同时统一圆润度、描边、块面、材质、密度、图标语言与明度层级。

### 14.2 重设计过度

错误：用户要求高清重置，却改变轮廓、元素、颜色和布局。  
纠正：重新使用原图为唯一内容依据，提示词中逐项锁定不可变内容。

### 14.3 画面过黑、过重

错误：深蓝黑占比过大，边框过粗，所有面板像重型金属。  
纠正：提高中间调，使用浅蓝/浅紫主体板，缩小深色面积，只保留一层清晰外轮廓。

### 14.4 画面过平

错误：水晶、怪物、按钮、环境同亮度。  
纠正：背景降对比，水晶和主按钮提亮，怪物缩小并降低饱和。

### 14.5 路径错误

错误：改变出生点、终点、闭环状态或魔法门朝向。  
纠正：以实机布局参考为唯一结构依据，逐段核对路径。

### 14.6 图标不够 Q、不够提炼

错误：颜色过多、转折过多、细小零件过多。  
纠正：先做纯剪影，删到只剩一个主体和一个辅助符号；用 3～5 色大块面重绘。

### 14.7 透视不一致

错误：水晶、法杖杆、基座、投影各自不同角度。  
纠正：先画统一中心轴和椭圆基线，再让所有结构服从同一俯视角。

### 14.8 序列帧抖动

错误：每帧主体大小、中心或外轮廓变化。  
纠正：锁定主体层，只动画内部纹理、发光和粒子；逐帧叠加检查。

### 14.9 抠图杂边

错误：绿幕侵蚀绿色图标，边缘带紫/绿杂色。  
纠正：换互补色底、降低去色范围、边缘收缩 1px；仍不合格则重绘独立素材。

### 14.10 切图不按原始图素

错误：用 AI 近似重画导致图标、角标和背板与效果图不一致。  
纠正：优先从分层源或无字素材图导出；确需重绘时以局部原图作严格形状参考并逐项比对。

## 16. 协作原则

- 先理解“不能变什么”，再考虑“怎么变好看”。
- 最新确认图优先于任何历史参考。
- 用户的局部反馈只授权局部修改。
- 不用“多做细节”代替“提高完成度”。完成度来自统一、比例、边缘、层级和可读性。
- 效果图、生产素材、运行资源是三个阶段，不能混为一谈。
- 切图不是截图裁剪；正式资源必须可复用、可伸缩、可换字、可切换状态。
- 每一次生成、下载、切图和入库都要可追溯、可回滚、可复验。
