# 战斗数值总表

> 版本：v0.1  
> 代码快照：2026-07-30  
> 运行数值源：`scripts/game_config.gd`、`scripts/chapter_one_config.gd`、`scripts/crystal_system.gd`  
> 本文用途：策划调参主表与变更记录；游戏运行时**只读取代码配置**，不读取本文。

## 使用规则

### 数值优先级

1. `GameConfig`、`ChapterOneConfig` 与战斗系统代码是唯一运行事实。
2. 本表记录当前运行值、计划调整值、设计意图和测试结论。
3. 本表与代码不一致时，以代码为准，并在“修改记录”中补齐差异。

### 调参流程

1. 在对应表格的“待调值”填写方案，并将状态改为“待测试”。
2. 记录测试关卡、结论和目标体验；通过后改为“待同步”。
3. 开发按“代码键”修改运行配置、模拟器与测试。
4. 验证通过后，用实际代码值回填“当前运行值”，清空待调值，状态改为“已同步”。

### 状态定义

| 状态 | 含义 |
|---|---|
| 已同步 | 本表当前值已与运行代码一致。 |
| 待测试 | 已有策划目标，尚未完成数值体验验证。 |
| 待同步 | 已通过测试，等待写入代码或等待代码验收。 |
| 废弃 | 保留历史信息，但不应进入当前运行内容。 |

### 2.2 持续伤害叠层规则（已同步）

| 规则 | 毒 | 火 |
|---|---|---|
| 叠加单位 | 一次命中目标增加 1 层。 | 一次火焰命中或溅射命中目标增加 1 层。 |
| 层数上限 | 4 层。 | 4 层。 |
| 单层伤害 | 以该次命中的攻击力和该次属性阶参数独立记录。 | 以该次命中的攻击力和该次属性阶参数独立记录。 |
| 单层持续时间 | `3.0 + 0.3 × (阶-1)` 秒。 | `2.0 + 0.2 × (阶-1)` 秒。 |
| 达到 4 层后再命中 | 替换剩余时间最短的一层，并以本次命中的伤害与时长重新计算该层。 | 替换剩余时间最短的一层，并以本次命中的伤害与时长重新计算该层。 |
| 双属性共存 | 毒与火各自独立计算，目标最多可同时拥有 4 层毒和 4 层火。 | 同左。 |
| 伤害结算 | 每秒结算一次，结算当刻所有存活层的伤害总和；只出现一次合计红色扣血飘字与红闪。 | 保留持续燃烧的实时扣血节奏；层数与每层 DPS 相加。增加橙色燃烧层数标记 `×1–4`，不重复刷屏。 |
| 层数可见性 | 怪物状态区显示毒图标与层数 `×1–4`。 | 怪物状态区显示燃烧图标与层数 `×1–4`。 |
| 中断续玩 | 每层的伤害、剩余时间和来源均需要保存与恢复。 | 同左。 |

> 默认取舍：满层后的新命中替换最早到期层，而不是无效或重置全部层。这样每次攻击始终有收益，同时不会突破 4 层伤害上限。

### 2.3 毒系连续集火与叠层规则（已同步）

| 项目 | 规则 |
|---|---|
| 攻击次数 | 合成 `N` 张时，产生 `N` 发连续攻击。 |
| 目标选择 | 始终攻击当前最前的怪物；仅当该目标死亡或到达水晶后，后续发数才转向下一只前排怪物。 |
| 单发直接伤害 | `基础攻击 × max(1, N-1) ÷ N`。 |
| 总直接伤害 | `基础攻击 × max(1, N-1)`，与普通合成的总直伤口径一致。 |
| 毒层施加 | 每次对存活目标的有效命中增加 1 层毒；同一合成可对同一目标连续叠层，最多 4 层。 |
| 目标不足 | 没有有效目标时，未发出的攻击直接结束；不产生空目标伤害或毒层。 |

**验收补充**

- 合成 3 张毒数字时，对当前最前怪物连续攻击 3 次；其存活时获得 3 层毒。
- 合成 5 张毒数字时，前排怪物存活则最多叠至 4 层；若其在过程中死亡，剩余攻击才转至下一只怪物。
- 毒系连续攻击不改变每个目标的 4 层上限，也不改变毒和火可同时存在的规则。

**验收条件**

- 同一属性连续命中 4 次时，目标显示 `×4`，总持续伤害为四层之和。
- 第 5 次命中后层数仍为 `×4`；只有剩余时间最短的一层被刷新。
- 毒与火可同时存在，互不覆盖；中断并续战后，层数、每层伤害和剩余时间保持一致。
- 毒每秒只有一次合计红闪与飘字，不因 4 层变为 4 次文字；火焰层数反馈可辨识但不刷屏。
