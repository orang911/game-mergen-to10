# 连锁合成与连击爆发 v1

更新：2026-09-09

## 目标

把一次玩家合成和其后由下落产生的自动合成视为一个完整的合成批次。棋盘先完成连锁，攻击元素按发生顺序展示，最后在同一个攻击窗口内同时结算。

## 当前规则

- 手动合成成功后，先完成下落和补充。
- 新棋盘满足现有相邻同等级合成条件时，自动继续合成。
- 一次批次最多进行 `GameConfig.CHAIN_MERGE_LIMIT` 次合成；初始值为 3，手动合成计为第 1 次。
- 每个自动合成都记录元素、来源等级、结果等级、合成数量、位置和顺序。
- 当前手动合成元素在攻击队列首位，自动合成元素按顺序追加。
- 队列元素依次显示，但不再分别等待攻击；所有元素在同一批次内同时发动。
- 属性自身的攻击规则保留，批次只负责统一目标快照和结算时机。
- 一次批次内不同元素达到 3 种时触发元素共鸣。重复元素不增加种类数。
- 当前共鸣倍率为临时程序基线：3/4/5 种元素对应 1.15/1.30/1.50，后续由战斗平衡和特效需求共同校准。
- 没有目标时不跨波次保留攻击队列。

## 结算顺序

```text
ROOT_MERGE
→ FALL_AND_REFILL
→ AUTO_CHAIN_SCAN
→ AUTO_CHAIN_MERGE
→ FALL_AND_REFILL
→ CHAIN_ATTACK_PREVIEW
→ CHAIN_ATTACK_BURST
→ FINAL_SETTLEMENT
```

攻击伤害在批次攻击的共同命中边界结算。这样不会出现第一种属性击杀最后一只怪后，后续属性丢失目标的问题。

## 代码边界

- `scripts/main_game.gd`：负责棋盘批次、自动连锁、上限和合成记录。
- `scripts/merge_chain_batch.gd`：保存批次事件、元素去重、共鸣等级和倍率。
- `scripts/combat_system.gd`：负责批量攻击、统一目标和共同伤害结算。
- `scripts/chain_attack_queue_view.gd`：当前程序占位的元素队列展示。
- `scripts/effect_system.gd`：负责队列展示和批次爆点反馈。
- `scripts/game_config.gd`：负责连锁上限、时序和临时共鸣基线。
