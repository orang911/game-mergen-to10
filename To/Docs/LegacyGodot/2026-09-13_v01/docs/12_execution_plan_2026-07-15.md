## 二、执行顺序

### P0：恢复可运行基线

1. 修复 `battle_layer.tscn` 对已删除背景资源的引用。
2. 修复 `battle_path_view.gd` 对旧路径贴图的加载，或明确改为当前路径实现。
3. 修复 `castle_view.tscn` 对已删除城堡受击资源的引用。
4. 用 Godot 4.7 执行编辑器解析和主场景启动检查。

验收：主场景启动时无资源加载错误、无脚本解析错误，能进入 Loading、主菜单和游戏局内。

### P1：重建当前版本 Web 包

1. 删除或隔离旧的 `builds/web_smoke` 输出，重新导出最新代码。
2. 保持 Web Threads 关闭，先验证普通 HTTP 部署。
3. 通过本地 HTTP 服务启动，不使用 `file://` 双击测试。

验收：桌面浏览器能够加载 `index.pck` / `index.wasm`，进入游戏后无关键 Console 错误。

### P2：玩法闭环冒烟

- `1 + 1 -> 2`：绿色 poison 弹道和命中特效。
- `2 + 2 -> 3`：蓝色 ice 弹道和减速效果。
- 黄色属性：连锁攻击可命中额外目标。
- 紫色属性：按概率触发暴击浮字和强化闪光，不产生持续状态。
- 红色属性：燃烧/范围溅射表现正常。
- 无怪物时合成仍显示行提示且不报错。
- 重开后无旧怪物、旧弹道、旧水晶计时器、旧提示横幅。
- 城堡归零和棋盘无解都能正确结束。

### P3：移动端与视觉收口

- 竖屏下棋盘不被路径、城堡、弹道和 HUD 遮挡。
- 弹体尺寸、拖尾强度、发射闪光和最短飞行时间达到可辨识标准。
- Loading 动画结束后 PLAY 可点击，返回菜单不会残留 Tween 或旧节点。
- 合成行横幅五行定位正确，重开后无残留。

### P4：数值验证

只调整配置，不在表现脚本里散写数值。重点记录：

- 小/中/大怪的击杀时间和漏怪压力。
- 水晶对低级合成断档的补偿是否足够但不喧宾夺主。
- 波次 1-3 的城堡耐久消耗。
- 五属性的实际可辨识度和强弱差异。

## 三、文档维护规则

- 运行时数值以 `scripts/game_config.gd` 为准。
- 当前已落地功能写进 `01_current_state.md`，不要继续写成“建议新增”。

- Godot 主场景无关键启动错误。
- 最新 Web 包由当前工作区重新导出。
- 桌面浏览器和至少一种移动端竖屏环境完成冒烟。
- 五属性、弹道、行提示、重开和失败流程通过检查。
